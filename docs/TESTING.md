# dsh-novel-forge 挂载后测试流程

适用对象：插件已通过 `dsh plugin add` / `--patch` / 桌面插件面板 **挂载并随宿主启动**。

预期成功的标志：宿主日志出现
`[novel-forge] 已就绪：http://127.0.0.1:端口（浏览器打开即可使用；服务随 DSH 退出而停止）`。

拿到 URL 的办法：
- CLI profile：`dsh --profile <name>` 的宿主日志；或控制台执行 `await ctx.novelForge.describe()`
- 桌面版：宿主日志/插件详情面板；缺省端口 7390（若配置 port=0 则为随机端口，以日志为准）

---

## 0. 前置检查（挂载前，可选）

```sh
node -v                        # 需 ≥ 18.17
node scripts/test-standalone.mjs   # 插件目录内：生命周期自测 10 项（含路线模板/动作注册）
node scripts/test-apply.mjs        # apply() 入口自测 9 项
node scripts/test-tools.mjs        # 工具集端到端 46 项（含「未选定故事路线即拒绝出大纲」门禁）
```

## 0.5 一键挂载自检（推荐入口，web/desktop 通用）

双击 **`check-mount.bat`**（或命令行加参），一次完成 环境→完整性→实例探测→服务抽检→
宿主状态→自动修正→报告落盘，退出码 0/3/2 即结论（0=挂载可用，3=降级待处理，2=硬性错误）：

```sh
check-mount.bat                          # 自动探测实例（默认尝试 7390）
check-mount.bat -url http://127.0.0.1:54321   # 指定宿主日志中的实际端口
check-mount.bat -autofix                 # 允许自动修正（等待重试/清理残留/隔离诊断）
```

- **即时反馈**：控制台逐行 `[PASS]/[WARN]/[FAIL]` + 结尾 RESULT 横幅；双击运行时窗口不自动关闭。
- **自愈能力**：`-autofix` 下会自动 ① 等待宿主完成插件启动（最多 15s 重试探测）；
  ② 清理数据目录 `.tmp` 残留；③ 执行"隔离诊断启动"——独立拉起插件内嵌应用验证插件本体，
  从而把问题收敛到"宿主侧未挂载/未启用"还是"插件本体损坏"。
- **错误文档**：每次自检自动生成 **`mount-check-report.txt`**（UTF-8、行式、机器可读：
  时间/环境/完整性/探测表/抽检/宿主提示/自动修正动作/结论与指引），可直接发给开发者；
  配合宿主日志（搜 `[novel-forge]` 或 `已就绪`）即可定位。
- **兼容性**：bat 壳为纯 ASCII（规避 cmd 对多字节批处理的解析差异），全部中文诊断由
  Node 引擎输出；实例探测走 HTTP，web(CLI) 与 desktop(electron) 宿主下行为一致；
  宿主进程提示同时识别 electron/dsh/node 进程。

## 1.5 会话内故事路线引导（v0.3.1 起为强制前置）

在 harness 会话里让模型写小说时，正确顺序是：

`novel_forge_new_project` → `novel_forge_seed_idea`（只给一段话也行）→ **`novel_forge_route_plan`（产出 2~5 条路线 + 大纲思路候选）**
→ 模型把候选逐条展示 → 用户回复编号（或自定义路线 / 明确说"你来定"）→ **`novel_forge_choose_route`**
→ `novel_forge_develop_project(stage=outline)` → 逐章写作。

验收要点：
- 未选定路线时调用 `novel_forge_develop_project(stage=outline)` 或 `novel_forge_chain(mode=full)`，
  应返回 `ok:false, code:'NEED_ROUTE'`（而不是把大纲直接生成出来）。
- `novel_forge_read_project(section='routes')` 能看到候选列表与 `ready` 状态。
- 引擎只配了「模拟引擎」时，`route_plan` 返回 `mode:'session'`：候选由会话模型自己写（附字段规范），
  经 `choose_route(routes=[…], index)` 入库——这样即使没配真实模型，也能拿到像样的路线与大纲思路。
- 模型没等你表态就用 `delegate` 会被拦下：缺 `note`（你的授权原话）时返回 `NEED_AUTHORIZATION`。
- 选定后再生成大纲：卷/阶段划分与结局走向应与该路线一致；`manuscript` 底稿导出里也有
  「故事路线与大纲思路」区块可核对。
- 网页界面同样有引导：点子页「① 故事路线 · 大纲思路」生成候选 → 卡片上「选定此路线」；
  大纲页顶部在未选定时会显示提示条。

## 3. 无 Key 端到端（模拟引擎，验证完整创作链）

浏览器操作：新建空白项目 → 点子页「🤖 深化当前创意」→ 采用 → **点子页「① 故事路线 · 大纲思路」生成候选 → 选定一条** →
设定/人物/大纲逐页生成并应用 → 大纲就绪后侧栏「⚡ 大纲→无人值守连载」→ 观察顶栏芯片跑完 →
审校页出现记忆档案 → 导出页下载 book.md 打开确认内容。

等价命令行（若需脚本化）：
`node scripts/verify-mounted.mjs <url>` 已覆盖 生成→应用→导出 的链路；
需要更长链路时复用主仓库 `scripts/acceptance.js <url>`（20 项，含无人值守连载+四种导出）。

## 4. 生命周期与数据

| 检查点 | 操作 | 预期 |
|---|---|---|
| 随宿主启停 | 退出宿主 → 重启 | 退出后端口关闭（`netstat -ano | findstr :端口` 无监听）；重启后日志重新出现"已就绪"，URL 可能变化（port=0 时） |
| 手动启停 | 宿主控制台调用 `ctx.novelForge.stop()` / `start()` | status 在 stopped/running 间切换；stop 后浏览器页面立即不可达 |
| 数据持久 | 重启前后各看一次项目库 | 你的书稿与设置仍在（数据目录 `插件目录/app/data/`：`projects/*.json` 书稿、`settings.json` 厂商配置与 Key） |
| 隔离性 | 插件实例与其它 NovelForge 实例并存 | 各自端口/数据目录独立，互不干扰 |

## 5. 真实模型接入（可选，Key 自备）

1. ⚙ 设置 → 厂商行（如 DeepSeek）填 Key → 「⛁ 测试连接」→ 预期 `✓ …连接成功（xx ms）`
2. 生成面板右上引擎切到该厂商 → 重跑一次「头脑风暴」→ 结果不再带"模拟引擎"标记
3. 失败时弹窗为中文自查清单（Key 前缀/平台归属/BaseURL/平台原文），按提示核对

## 6. 卸载与清理

```sh
dsh plugin --profile <name> remove dsh-novel-forge   # CLI profile：移除依赖与配置层
# 桌面版：插件面板中移除；或直接删除 profile 中对应 bundle 行
```
数据默认保留在插件目录 `app/data/`（卸载插件前如需保留书稿：先导出 backup.json，或整目录备份 `app/data`）。

## 常见问题

- **日志没有"已就绪"**：查 `[novel-forge] 启动失败` 详情 —— 多为 Node 缺失/版本低、端口被占用、`startTimeoutMs` 不足。
- **地址打不开**：确认是宿主日志中的端口；若 DSH 跑在容器/远程，需要端口映射或改 `host: 0.0.0.0`（自行评估安全）。
- **想固定端口**：patch 的 `config.port` 改为具体值（如 7390）后重启宿主。
