## [0.3.1] - 2026-09-11

### Added
- **Обязательное направляющее сопровождение по сюжетному маршруту (исправление логики вызовов)**: сколько бы материала ни дал пользователь — даже одно предложение или один абзац —
  сначала необходимо выдать 2–5 кандидатов «сюжетный маршрут (план и подход к структуре)», показать каждый вариант пользователю, записать выбор и только затем генерировать план.
  - Новый инструмент `novel_forge_route_plan`: выдаёт кандидатов (подход к структуре / маршрут по этапам / нарастание основного конфликта / направление финала / сквозные предзнаменования / компромиссы и риски / рекомендация ИИ),
    принимает пользовательский текст прямо в `paragraph` и при слишком тонкой заявке сначала автоматически её углубляет; возвращает `mustChoose=true` и инструкцию «обязательно показать пользователю».
  - Новый инструмент `novel_forge_choose_route`: записывает выбранный маршрут через `index` (пользователь выбрал номер), `custom` (собственный маршрут пользователя) или `delegate` (пользователь явно уполномочил ИИ выбрать);
    без выбора возвращает `NEED_CHOICE` — решать за пользователя нельзя.
- **Этап маршрута в движке** (единственный источник — автономная версия, зеркалируется в плагин): новый шаблон `t_route_plan` + новое действие `route_plan` (stage=idea), документ проекта `routes`
  (кандидаты + выбранный), переменная `{{routeText}}`, внедряемая в `t_outline_generate` / `t_outline_extend`.
- **Подложка и списки**: в экспорт `manuscript` добавлен блок «сюжетный маршрут (план и подход к структуре)»; список проектов несёт статус маршрута; на странице идеи появилась карточка кандидатов маршрута (выбрать / принять рекомендацию ИИ / сменить набор).

- **Кандидаты, создаваемые в сессии (чтобы сопровождение было осмысленным)**: если в движке настроен только офлайн-симуляционный движок (или вызов движка не удался), `novel_forge_route_plan` возвращает
  `mode:'session'` + спецификацию полей, и 2–5 вариантов маршрута создаёт **сама модель сессии** (чтобы не получать заглушки «(симуляция)»), после чего они записываются через
  `novel_forge_choose_route(routes=[…], index/custom/delegate)`; параметр `source` позволяет принудительно задать `engine` / `session` / `auto`.
- **Запрет решать за пользователя**: `novel_forge_choose_route` без выбора возвращает `NEED_CHOICE`; `delegate=true` требует подлинных слов авторизации пользователя
  (в `note`), иначе возвращается `NEED_AUTHORIZATION`.

### Changed
- **Шлюз (жёсткий)**: без выбранного маршрута `novel_forge_develop_project(stage=outline)` и `novel_forge_chain(mode=full)` сразу возвращают
  `NEED_ROUTE` и отказываются выполняться (только при явной просьбе пользователя «пропустить сопровождение» можно передать `allowUnrouted=true`, и результат помечается как непроведённый через сопровождение).
- Остальные этапы (flesh/world/characters) по-прежнему можно продвигать, но с напоминанием «маршрут ещё не выбран»; в `novel_forge_read_project` добавлено представление `routes`.
- Конвейер без контроля `full` теперь сначала добавляет шаг `route_plan`, и план строится по маршруту, рекомендованному ИИ (при присутствии человека выбор всё равно следует делать вручную).
- Общее число сессионных инструментов 18 → 20 (14 инструментов `novel_forge_*` + 6 инструментов `novel_forge_cap_*`); шаблоны 24 → 25; действия движка 18 → 19.
- Версия плагина 0.3.0 → 0.3.1 (синхронизирована с движком 0.4.1).

### Fixed
- Исправлен дефект логики вызовов, когда по одному абзацу пользователя план генерировался сразу и без всякого контроля: выбор маршрута стал обязательным предварительным условием для плана,
  а промпт плана всегда несёт выбранный маршрут, поэтому план больше не расползается.

### Verify
- Самопроверка плагина полностью зелёная: standalone 10/10 · apply 9/9 · tools 46/46 (включая шлюз `NEED_ROUTE`, `NEED_AUTHORIZATION` и случаи «один абзац / симуляционный движок проходит сопровождение»).
- Сторона движка: `test-route.js` 17/17 · `test-gen.js` 43/43 · `test-api.js` 26/26 · `test-pipeline.js` 21/21 · `acceptance.js` 20/20 · рендер 9/9 · взаимодействие 11/11.
- Зеркало движка `engine-mirror verify`: исходник/плагин 32 vs 32, нулевой дрейф.

## [0.3.0] - 2026-09-07

### Added
- **Модернизация возможностей**: позиционирование плагина повышено до «универсальной творческой оболочки», встроенный NovelForge стал хостингом возможностей, добавлены три категории возможностей content / doc / email, все они вызываются через единый генеративно-прикладной движок.
- **Новые сессионные инструменты возможностей (6)**: `novel_forge_capabilities`, `novel_forge_cap_create`, `novel_forge_cap_set_source`, `novel_forge_cap_analyze`, `novel_forge_cap_run`, `novel_forge_cap_read`.
- **Расширение служб**: `ctx.novelForge.capabilities()` возвращает перечень возможностей (novel/content/doc/email и действия).
- **Зеркалирование каркаса возможностей движка**: реестр `app/server/capabilities.js`, поле `cap` проекта, `/api/capabilities`, `/api/projects/:id/workspace`.
- **Многоязычность**: i18n фронтенда (`app/public/js/i18n.js`, полные китайский/английский + французский/русский/испанский/португальский с запасным китайским), языковой селектор в верхней панели; поле `language` проекта поддерживает написание на любом целевом языке.
- **Рабочая станция возможностей на веб-странице**: `app/public/js/views/capStudio.js`.

### Changed
- Общее число сессионных инструментов выросло с 12 → 18 (12 инструментов `novel_forge_*` для романов + 6 инструментов возможностей `novel_forge_cap_*`).
- Общее число действий движка (этапы novel + действия возможностей); шаблоны 18 → 24.
- Тексты UI фронтенда полностью переведены на `t()` (база zh, непокрытые ключи откатываются к китайскому).
- Версия плагина 0.2.0 → 0.3.0 (синхронизирована с движком 0.4.0).

### Fixed
- Обновлены утверждения самопроверки плагина под новое количество возможностей (24 набора шаблонов / 18 инструментов).
- Исправлены 3 ошибки баланса скобок ESM, введённые зеркалированием инструментов возможностей (представления `bible/audit/outline` внутри приложения).

### Verify
- Самопроверка плагина полностью зелёная: standalone 8/8 · apply 9/9 · tools 26/26.
- Зеркало движка `engine-mirror verify`: исходник/плагин 32 vs 32, нулевой дрейф.

## [0.2.0] - 2026-09-06

### Added
- Первая оформившаяся плагинизация (комбинированный пакет DSH): встроенное зеркало движка + служба жизненного цикла `novelForge` + 12 сессионных инструментов `novel_forge_*`.
- Исправлены две ключевые проблемы времени выполнения: `process.execPath` не является node под хостом Electron, у логгера хоста нет `.log`.
- `resolveNode()` обрабатывает различия между хостами рабочего стола (Electron)/CLI; конфигурационный слой `cordis.patch.yml` (строка службы + строка инструментов).
- Самопроверка монтирования `check-mount.bat` → `mount-check-report.txt`.
